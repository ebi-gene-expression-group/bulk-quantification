# bulk-quantification
Bulk quantification workflow and supporting scripts

## Run one experiment in batches

This pipeline can split a large experiment samplesheet into smaller batch samplesheets and run nf-core/rnaseq once per batch.

- Use `--batch_size 0` (default) to keep current behavior: one nf-core run for the whole experiment.
- Use `--batch_size N` (for example, `100`) to run the experiment in chunks of `N` samples.

Final output parity is preserved:

- Without batching (`--batch_size 0`), results are produced directly in the standard output layout.
- With batching (`--batch_size > 0`), per-batch runs are merged and then materialized into the same canonical final locations for MultiQC and STAR-Salmon merged matrices.

For batch runs, the pipeline also reconstructs an nf-core-like output layout in the main output directory (including sample/alignment directories under quantifier folders such as `star_salmon/`). This keeps downstream file discovery consistent.

### Example

```bash
nextflow run main.nf \
	--EXP_ID E-MTAB-1234 \
	--batch_size 100 \
	-profile atlas
```

### What gets created

- Batch samplesheets are generated internally as `batch_000001`, `batch_000002`, ...
- Each batch is processed by a separate nf-core/rnaseq invocation.
- Batch outputs are written under:

```text
<outdir>/batches/batch_000001/
<outdir>/batches/batch_000002/
...
```

- Per-batch trace files are written as:

```text
<outdir>/<EXP_ID>_batch_000001_trace.tsv
<outdir>/<EXP_ID>_batch_000002_trace.tsv
...
```

- Per-batch MultiQC reports are kept as generated by nf-core/rnaseq.
- Each successful batch also removes its own nested nf-core work directory automatically.

### Automatic merged MultiQC for batch runs

When `--batch_size` is greater than `0`, the pipeline also runs an automatic final merge step that combines all per-batch `multiqc_data` directories into one report.

- Output directory: `<outdir>/multiqc_merged/`
- Combined report: `<outdir>/multiqc_merged/multiqc_report_all_batches.html`
- The combined report is sanitized in a final post-merge step (path placeholders applied for reference/work/output/repo paths).

### Automatic merged count matrices for batch runs

When `--batch_size` is greater than `0`, the pipeline also merges STAR-Salmon count matrices across all successful batches.

- Output directory: `<outdir>/merged_counts/`
- Files created:
	- `<outdir>/merged_counts/star_salmon/salmon.merged.gene_counts.tsv`
	- `<outdir>/merged_counts/star_salmon/salmon.merged.transcript_counts.tsv`
	- `<outdir>/merged_counts/star_salmon/salmon.merged.gene_tpm.tsv`
	- `<outdir>/merged_counts/star_salmon/salmon.merged.transcript_tpm.tsv`

This merge step is adapted from the matrix-merging approach used in atlas-gtex-bulk (`merge_existing_star_salmon_matrices.py` and `merge_nfcore_rnaseq_batches.py`).

In addition, full directory layout reconstruction in batch mode is adapted from atlas-gtex-bulk `merge_nfcore_rnaseq_batches.py` logic.

For batch runs, merged outputs are also copied into canonical final paths so downstream consumers can read the same locations regardless of batching mode:

- `<outdir>/multiqc/star_salmon/multiqc_report.html`
- `<outdir>/star_salmon/salmon.merged.gene_counts.tsv`
- `<outdir>/star_salmon/salmon.merged.transcript_counts.tsv`
- `<outdir>/star_salmon/salmon.merged.gene_tpm.tsv`
- `<outdir>/star_salmon/salmon.merged.transcript_tpm.tsv`
